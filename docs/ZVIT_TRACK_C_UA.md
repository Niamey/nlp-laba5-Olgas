# Звіт: Track C — GitHub Issue Triage Agent

Шаблон для письмового звіту до PDF. Заповни розділи власними формулюваннями та числами після запуску eval.

---

## 1. Мета та постановка

- **Що робить агент:** тріаж GitHub issues (класифікація, дублікати, зона коду, застарілі тикети тощо).
- **Обмеження:** тільки інструменти через MCP + LLM; обов’язкове посилання на текст issue / результати пошуку (grounding).

---

## 2. Архітектура агента

- **Оркестратор:** LangGraph (стан, умовні ребра, HIL interrupt).
- **MCP:**
  - власний сервер (GitHub issue, пошук схожих, … — перелічи з виводу `python main.py --list-mcp`);
  - другий сервер (наприклад `mcp-server-fetch`) — якщо увімкнено через `FETCH_*` у `.env`.
- **LLM:** Google Gemini (`GOOGLE_API_KEY` / `GEMINI_API_KEY`).

*(Встав схему графа з README або експорт з інструменту.)*

## 4. Політики безпеки та відмови

- Коли агент **відмовляється** (немає доступу, поза скоупом, шкідливий запит).
- Як **не вигадувати** номери issues (тільки з `search_similar_issues` / issue body).

---

## 5. Оцінювання (evaluation suite)

- **Набір:** `evaluation/tasks.json` — скільки задач, розподіл по категоріях (happy_path / ambiguous / adversarial / should_refuse).
- **Метрики:** середній бал, grounding, тривалість — з `summary.json` після `python main.py --eval --output trajectories/` і `python scripts/show_eval_summary.py`.
- **Траєкторії:** у кожному JSON тепер є `message_trace` (компактні прев’ю повідомлень + `usage_metadata` / `response_metadata`) та `token_usage_est` для аналізу витрат токенів.
